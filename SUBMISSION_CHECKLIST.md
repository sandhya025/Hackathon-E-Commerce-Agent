## 💡 Key Insights for Your Next Project

### When Agentic Orchestration is Necessary
1. **Financial decisions** — Math must be exact, not approximate
2. **Policy enforcement** — Hard rules, not soft predictions
3. **Multi-source verification** — Need to check external data
4. **Pattern recognition over time** — Require persistent memory
5. **Audit requirements** — Need visible reasoning trail

### Design Principles That Worked Here
1. **Separate concerns** (policy ≠ finance ≠ fraud)
2. **Verify before deciding** (tools provide facts, LLM reasons)
3. **Include fallback** (policy layer catches LLM mistakes)
4. **Enable transparency** (audit trail for every decision)
5. **Make it scalable** (update rules without retraining)

### What Didn't Matter Much
- ❌ Number of agents (1 orchestrator working > 5 sequential)
- ❌ LLM size (even small models work with good tools)
- ❌ Prompt complexity (structured over elaborate)

### What Mattered Most
- ✅ Deterministic components (financial math)
- ✅ Proper tool design (each does one thing well)
- ✅ Evidence-based reasoning (LLM coordinates verified facts)
- ✅ Fallback safety (policy layer catches breaks)
